# 04. AI and AIR Architecture (Phase 3 Implemented)

## Overview
This document describes the implemented foundation for Application Intermediate Representation (AIR) and provider-neutral AI orchestration within ForgeFlow AI.

## Status

## Application Intermediate Representation (AIR)
AIR is the canonical contract connecting source analysis, security scanning, and migration planning. It is deterministically generated by the `DeterministicAnalyzer` without executing untrusted customer code.

Key Models (Implemented):
- `AIR`
- `Route`, `Screen`, `Component`, `Form`, `APIEndpoint`
- `StateManagement`, `AuthStrategy`, `AuthorizationModel`
- `Dependency`, `Asset`, `BusinessRule`, `Integration`
- `SecuritySignal`, `MigrationConstraint`

Every semantic inference inside the AIR tracks `Provenance` (confidence, source file, detection method).

## AI Orchestration
The AI Orchestration layer (`AIOrchestrator`) manages interactions with AI providers. It enforces the following boundaries:
1. **Context Isolation**: Customer source code is isolated from System Instructions and Trusted Metadata.
2. **Secret Redaction**: Raw secrets are stripped by the `SecretRedactor` before transmission.
3. **Resource Limits**: Strict limits on input/output tokens, timeout duration, and retries.
4. **Audit Tracking**: All runs are tracked via `AIRunAudit` storing metrics and cost estimations without logging raw sensitive content.
